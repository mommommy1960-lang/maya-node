# Cloudflare staging port — not deployed

Separate opt-in implementation of the dispatch gate using D1 conditional updates and a five-minute Cron Trigger. Only queued jobs can be claimed. Claim is the cancellation cutoff. Unknown, sent and interrupted committed jobs never automatically retry. Gmail uses offline OAuth with gmail.send permission, with refresh and access tokens handled only as Worker secrets. Provider acceptance does not prove inbox delivery. No current ChatGPT connector credentials are exported.

Sending defaults to disabled. This is not a migration of existing Maya state, a production deployment, or a claim of exactly-once delivery. Preserve all previous SQLite records; do not copy approved jobs to both queues. New staging jobs require fresh exact-payload approval. Controller token permits enqueue/approve/cancel: restrict it to a trusted human controller; never supply it to untrusted agents. This port has status counts and log alerts, but no external notification sink yet. Free-plan quotas can halt processing. Scheduled batches are capped at three messages and CPU usage must be measured on Cloudflare before activation.

Deployment requires a Cloudflare account on Workers Free, authorized deployment access, and a separate Google OAuth app/consent flow. There is no connected Cloudflare deployment capability in this session. Do not paste credentials in chat or commit them. Using Cloudflare dashboard or Wrangler: create D1 database maya-mail-staging; replace the database_id placeholder in wrangler.jsonc; execute schema.sql remotely; set secrets CONTROLLER_TOKEN, GMAIL_CLIENT_ID, GMAIL_CLIENT_SECRET, GMAIL_REFRESH_TOKEN and MAIL_FROM; deploy while SEND_ENABLED=false. Authenticate the Google mailbox using offline consent and gmail.send scope. External Google OAuth apps in Testing can have seven-day refresh-token expiry; resolve that lifecycle before unattended rollout.

Before enabling sending, test authenticated enqueue, exact-payload approval, cancellation, two competing dispatches, database reopening, failed OAuth, provider timeout and missing receipt. Then enable sending for a fresh approved inbox-only job, confirm delivery and recorded receipt, verify duplicate blocking and notifications. No credentials or infrastructure have been provisioned here.

Local verification: node --test deploy/cloudflare/test.mjs. Tests use real local SQLite through Node's experimental node:sqlite, not Cloudflare D1. Hosted runtime, quota, restart and live Gmail tests remain required.
