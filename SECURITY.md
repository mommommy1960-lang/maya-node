# Security Policy

## Reporting
Do not open a public issue for suspected credentials, private data, exploitable vulnerabilities, or unpublished security-sensitive design information. Contact the repository owner privately through an established private channel.

Do not include live credentials, private keys, tokens, personal information, confidential partner material, or exploit-ready sensitive data in a public report.

## Evidence handling
Preserve the affected commit/ref, file path, observed behavior, and minimum reproduction information necessary to evaluate the report. Do not broaden access or publish sensitive details merely to demonstrate the problem.

## Disclosure boundary
Public visibility is not authorization to access systems, accounts, private repositories, partner systems, or data outside the repository. Testing must remain within systems and data the tester is authorized to use.

## Sensitive changes
Changes to workflows, security policy, licenses, legal notices, governance controls, release controls, or ownership boundaries require heightened review and should not be merged solely because ordinary functional tests pass.
