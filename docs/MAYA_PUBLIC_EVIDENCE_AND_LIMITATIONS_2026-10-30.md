# Maya Node — Public Evidence and Limitations
**Review date:** October 30, 2026  
**Purpose:** Public-safe evidence summary for partner discussions. This is a dated summary, not a live audit feed, independent assessment, privacy policy, service-level agreement, or launch authorization.

## Current description

Maya Node is a bounded permission-and-action-record prototype. Its current demonstration is intended to show how a narrowly defined request can be prepared, explicitly authorized, executed or blocked, and represented in reviewable records.

**Core principle:** Technical capability does not confer authority.

The managed Sites demonstration, Cloudflare Worker Preview, local test environment, and browser-only fictional demonstration are distinct environments. Evidence from one must not be presented as proof of another.

## Dated evidence

### October 28 — v18 engineering hardening
The October 28 engineering record documents 87 automated tests, local D1 integration, a seven-scenario acceptance suite, TypeScript validation, and a successful production build for the v18 hardening work. These are dated engineering results, not a fresh v20 test run, independent security certification, or proof of all hosted customer paths.

### October 29 — managed Sites version 20
The existing public managed Site was confirmed active at version 20. In a founder-authenticated session using invented text:
- A defined text-file request was prepared, explicitly authorized, executed, and read back through the connected service; the returned content and independently calculated SHA-256 matched the intended text.
- A separate request was authorized, revoked, and then blocked; the hosted interface recorded the `permission_revoked` outcome and offered no download control.
- The browser reported a download event, but the downloaded artifact was not independently retrieved for byte-for-byte verification. This was not physical Android tablet acceptance.

### October 29 — deletion of two synthetic fixtures
With explicit founder approval, one completed and one revoked synthetic fixture were deleted through the authenticated hosted interface. Follow-up checks found both fixture articles absent, neither request ID in the checked request/output/event tables, and the deleted completed file returned `File not found`. The original peer sample and pre-existing records were preserved.

This is evidence for those two named synthetic fixtures and checked active records only. It does not establish deletion from backups, provider logs, device-local copies, every session or endpoint, or every customer account.

### October 29 — payment setup status
Test-mode Stripe objects were created for a possible future one-time offer. This is not an enabled checkout:
- `MAYA_BILLING_ENABLED=false`.
- The hosted server API key is not provisioned.
- No end-to-end checkout, webhook, entitlement, refund, dispute, expiry, or payment-failure rehearsal is complete.
- No live charge was made.
- The $25 amount is a future proposal, not an active offer or request for payment.

## What is not established

- Production-ready customer-facing automation or general-purpose AI replies.
- Autonomous control of third-party applications or live email dispatch.
- Full endpoint coverage for customer-controlled access, review, and deletion.
- Independent proof of cross-account isolation.
- Immutable, permanently retained, externally signed, or independently anchored receipts.
- Hosting backup/PITR configuration, provider-log expiry, deleted-data non-resurrection, or successful isolated hosted restoration.
- Verified physical tablet alert receipt, consenting backup responder, or defined support coverage.
- Written external pilot permission, independent customer acceptance, regulatory certification, or measured business outcomes.

## Current safe scope

Exploratory partner conversations and founder-guided demonstrations using invented information only. Do not request or process customer records, credentials, production access, payment, or live operational authority. Exclude high-stakes workflows such as healthcare, lending/credit, tenant screening, legal eligibility, school discipline, and live funds movement.

## Public wording

Use: “bounded permission-and-action-record prototype,” “founder-guided synthetic demonstration,” “dated test evidence,” and “capabilities still under verification.”

Avoid: “immutable/permanent audit trail,” “exactly-once execution” as a general guarantee, “zero data transmission,” “dedicated isolated customer environment,” “instant freeze,” “complete deletion,” “production ready,” “compliance certified,” “five-day delivery,” “24-hour response,” or any claim of an active paid pilot.
